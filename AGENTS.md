# Правила проекта

## Назначение

Этот каталог предназначен для мобильной 2D Idle-RPG игры про автоспорт, гонки и тюнинг. Игра использует idle-прогрессию в духе `Legend of Mushroom`, но содержит только автоспортовые механики: заезды, улучшение машины, экипировку, чемпионаты и экономику. Бои, стрельба и оружие не входят в проект.

## Граница текущей задачи

На этапе настройки разрешено создавать и изменять только проектные правила, документацию и служебные файлы. Игровой код, игровой HTML, ассеты и реализацию механик не писать без отдельного запроса на разработку.

## Техническое решение для будущей реализации

- Один самодостаточный `index.html`.
- Только HTML5, CSS и чистый JavaScript без фреймворков и внешних runtime-зависимостей.
- Canvas использовать для гоночной сцены и анимации.
- SVG использовать для интерфейсных иконок, простых векторных элементов и масштабируемых декоративных деталей.
- Состояние игры хранить локально через `localStorage` с версионированием схемы сохранения.
- Интерфейс проектировать mobile-first, с поддержкой touch-событий и клавиатуры для desktop-проверок.
- Внешние CDN, шрифты, трекеры, сетевые API и обязательная авторизация не использовать.

## Правила разработки

- Не оставлять заглушки вида `TODO`, `остальной код здесь` или неработающие кнопки.
- Каждая пользовательская кнопка должна иметь рабочее состояние, обратную связь и корректно обрабатываться при повторном нажатии.
- Игровой цикл должен корректно работать при сворачивании вкладки, скачках времени и восстановлении сохранения.
- Таймеры idle-прогресса ограничивать разумным офлайн-интервалом, чтобы пропуски времени не ломали экономику.
- Экономику, формулы прогрессии и баланс держать в одном читаемом блоке конфигурации.
- Все данные, пришедшие из `localStorage`, валидировать и безопасно восстанавливать при повреждении.
- Уважать `prefers-reduced-motion`, не полагаться только на цвет и поддерживать читаемый контраст.
- Не добавлять боевые сущности, оружие или стрельбу под другими названиями.

## Проверки перед завершением будущей реализации

- Открытие `index.html` напрямую в браузере без сервера.
- Проверка мобильной ширины и touch-взаимодействий.
- Проверка старта, паузы, завершения заезда и повторного заезда.
- Проверка покупки и применения улучшений, начисления валюты и офлайн-прогресса.
- Проверка сохранения, перезагрузки, повреждённого сохранения и сброса прогресса.
- Проверка отсутствия ошибок в DevTools Console.
- Проверка через Playwright при наличии `npx`, с артефактами в `output/playwright/`.

## Работа с возможностями Codex

Использовать минимальный достаточный набор локальных возможностей. Для будущей разработки применять `superpowers:brainstorming`, затем `superpowers:writing-plans`, а перед заявлением о готовности `superpowers:verification-before-completion`. Для браузерной проверки использовать локальный `playwright`. `imagegen` подключать только если понадобятся растровые ассеты. Подключение внешних приложений и установка плагинов не требуются для базового single-file проекта.

## Стиль изменений

- Не добавлять зависимости, сборщики и конфигурацию без отдельной необходимости.
- Не менять файлы вне этой папки без явного запроса.
- Не создавать субагентов для обычной работы над этим проектом.
- Предпочитать небольшие, проверяемые изменения и краткие отчёты по результату.
